# Behavior parity matrix

> [!NOTE]
> On this page, compare the reference uploader with the intended open-source product so preserved behavior and deliberate changes are reviewed rather than assumed.

## Decision values

- **Preserve:** Keep the user-observable behavior, though the implementation may change.
- **Change:** Ship a different documented behavior with migration guidance and regression tests.
- **Remove:** Do not ship the behavior; document the replacement or unsupported status.
- **Pending:** Allowed only while Steps 1–2 are active. Step 2 cannot close with Pending entries.

## Reference conflicts

- `BULK_UPLOAD_CONFIG_GUIDE.md` describes Slack notification settings as operational, while `ARCHITECTURE.md`, `bulkRecordUploadGuide.html`, and `BulkRecordUploadLogTriggerHandler` state that the integration is not implemented. The runtime no-op is authoritative; Slack is deferred and its fields cannot ship in core.
- `ARCHITECTURE.md` and the presentation draft describe a Flow handler and `SlackEnvelope__e`, but neither Flow metadata nor that event exists. Both are promised-only behavior and remain deferred.
- The presentation draft says every completed upload publishes a platform event, while the upload-log trigger handler is a no-op. Existing generic event metadata and tests do not prove completion publication.
- `SPEC-archive-and-row-numbers.md` labels archive and row-number behavior as a pending draft, while source and tests implement both. The observed runtime behavior is recorded in the matrix; the target decision remains open until Step 2.
- `Return_All_Fields__c` sounds like an all-object-field option, while the batch implementation operates on configured and uploaded projections. The target contract must use bounded configured fields only.

## Decision rationale and documentation

- Preserve decisions retain useful observable behavior while replacing the implementation with the security and architecture boundaries in [ADR-0002](../decisions/ADR-0002-product-contract.md).
- Change decisions remove ambiguous field identity, unbounded projections, overwritten timestamps, raw handler names, and authorization-by-location/group text. Their migration effects and acceptance tests are recorded in the matrix.
- The completion event is removed because the reference publisher is a no-op and no minimal subscriber use case or payload contract exists. It remains in the approved deferred inventory.
- Canonical subscriber references are [Product contract](../../docs/reference/product-contract.md), [CSV and results contract](../../docs/reference/csv-and-results-contract.md), [Package and compatibility](../../docs/reference/package-and-compatibility.md), and [Unsupported features](../../docs/reference/unsupported-features.md).
