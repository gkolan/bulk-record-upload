# Research-to-production map

> [!NOTE]
> On this page, map each reference artifact to an owned production responsibility and reviewed disposition before any source is reimplemented.

## Required disposition values

- **Reimplement:** Recreate the behavior in project-owned source using the approved architecture.
- **Adapt with attribution:** Adapt only after license review records the allowed use and required notice.
- **Defer:** Exclude from the current release and add it to `deferred-integrations.md` when it is an integration or promised feature.
- **Discard:** Exclude because it is stale, test-only outside its test boundary, unsafe, duplicated, unsupported, or unnecessary.

The [reference artifact inventory](../../docs/evidence/01-baseline-and-inventory/reference-artifact-inventory.csv) is the authoritative one-row-per-file appendix to this responsibility map. Step 1 must expand this seed table to one row per inventoried artifact. ## Completion checks

- Every inventory row maps to exactly one row here or one explicitly enumerated mechanical group.
- Every production owner names one responsibility and fits the Step 4 architecture.
- No Defer item has deployable core metadata or active UI.
- No Adapt with attribution item proceeds without a compatible license decision.
- Discarded items have a reason and do not appear in manifests, packages, npm archives, or public docs.
