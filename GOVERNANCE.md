# Governance

## Maintainer responsibilities

Maintainers protect the product contract, security boundary, package compatibility, test evidence, and published documentation. At least one maintainer reviews source changes; security- or release-sensitive changes require a second reviewer when the project has two available maintainers.

Decisions that change packaging, public contracts, supported releases, limits, or security require a written rationale and maintainer review in the pull request. Update the corresponding public contract or architecture guide when a decision is accepted. Local specifications and review notes are not contributor prerequisites.

## Releases

A release owner follows [RELEASING.md](RELEASING.md), retains verification as release or pull-request artifacts, and does not promote with an open release gate. Maintainer org access follows the policy in [CONTRIBUTING.md](CONTRIBUTING.md).
